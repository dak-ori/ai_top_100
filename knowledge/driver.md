# 구방만 기사 제공 문서 요약 (2026-10-31 작성)

원문은 `구방만_interview.md`. 문서 기준일은 가상 날짜 **2037-06-30**. 택배 계약서 PDF는 `sources/택배계약서.pdf`와 같은 파일이며(바이트 동일) HANDOFF §6의 조문 요약을 쓴다 — 직접 재독은 아직 안 함.

## 1. 구방만 발언 요지

- **집하 시각 기준은 집하 스캔 기록 시각.** 기사가 "인계했다"고 말한 시각과 스캔이 다르면 스캔이 기준.
- **송장 등록 후 조회에 뜨기까지 3~5시간.** 그 사이 조회에 안 보이는 것은 정상.
- 상온 농산과 냉장·냉동은 보관 조건이 달라 **합배송 제한**.
- 모른다고 한 것: 결항 판단 기준, 재개 시점 결정 주체, 인수 전 고객에게 알릴 내용, 하루 적재 한도, 파손·분실 시 조사 순서(로트·분실 조사 절차), 영업일 달력·출고 요일 문서. 임의로 설명하지 않겠다고 함.
- 계약 조문은 이민준 운영자가 안다. 작황은 박수복 어르신, 수산물 조업·입고는 홍이장이 안다.
- ⚠ 5번째 질문(부재 시 대체 경로 박민아) 답변이 4번째 답변과 똑같이 붙어 있음 → 붙여넣기 오류 가능. **박민아 인계 기준은 아직 답을 못 받은 상태.**

## 2. 시원배송 결항·집하 기록 (xlsx, 관리 구방만)

**기록 확인 기준(§3)**
- ① 작황과 운송은 별개. 운송 결항만으로 농산 피해나 갯마을 조업 중단을 단정하지 않는다(각각 「교동마을 작황·재해 기록」, 「갯마을 조업·입고 기록」에서 확인).
- ② `—`는 확정된 사실이 없다는 뜻이지 "지연 없음"도 "결항 발생"도 아님. ③ `정상`은 확인 결과 지연 없음으로 `—`와 다름. 지연 가능성 사전 통보 ≠ 실제 결항.
- ④ 일지는 사후에 채워짐, 예보 행에 소급해 덮어쓰지 않음.
- ⑤ **간선 재개와 집하 재개는 다른 시점일 수 있음.** 일요일에 간선이 풀려도 집하는 다음 영업일부터, 재개 후에도 밀린 물량 순차 처리.
- ⑥ 경미한 지연은 하자가 아님. 행의 존재만으로 배상 사유 확정 안 함.
- ⑦ **송장 등록 ≠ 택배 인수.** 집하 전후 책임 구간은 택배사 계약서 제3조.

## 3. 봇 설계 함의

- 고객이 "송장 떴는데 왜 안 와요" → 송장 등록과 집하(인수)는 별개, 조회 반영 3~5시간 지연은 정상, 결항 기간엔 산지 대기 중이라고 사실만 안내(귀책·배상 단정 금지, 결항은 LOGISTICS 이관 대상 판단은 에스컬레이션 절차서 §2 참고).
- 결항 사유 인수 전 취소는 판매환불규정상 출고 지연 취소 전액환불(권한 위임표 §4⑥ 재량 항목)과 재출고 선택지로 연결(공개 TC에 해당 패턴).
- 작황·조업 확인이 필요한 질문은 운송 기록으로 단정하지 말고 각 기록 소관(박수복·홍이장)으로.

## 4. 업무 인계 대장 + 박민아 수첩 (사진 2장, 5번째 질문 정정 답변)

5번째 답변은 정정되어 들어옴: 인계 기준은 구방만도 모름. 인계 기록은 **조합 사무실 종이 대장**(온라인 조회 불가). 구방만은 운행 수첩을 쓰지 않아, **종이 대장에 없는 것은 구방만 쪽에 남은 기록 없음.** 대신 맡은 쪽 기록은 박민아가 안다.
