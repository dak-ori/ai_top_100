# 디브리프 초안 — 교동마을 산지직송 고객 상담 에이전트

> 초안이다. 아직 하지 않은 일의 결과는 쓰지 않았고, 숫자가 필요한 곳은 `[오너 확인: …]`로 비워 두었다. 제출 전에 오너가 채우고 문장을 다듬는다.

## 1. 강점 — 어떤 상황을 잘 처리하도록 설계했고 그 이유는

이 에이전트는 하나의 문의를 말풍선 하나, 500자 이하로 끝내는 일에 가장 공을 들였다. 심사가 정확도뿐 아니라 말풍선 수와 글자 수, 응답 속도(p95)를 함께 보기 때문이다. 정책이 부딪히는 문의를 위해 증빙 서열(자사 기록과 제3자 발행물이 당사자 제출물보다 우선), 에스컬레이션 레인 판정(손해배상은 LANE3, 신원·보안·안전은 LANE2, 판단이 서지 않으면 LANE2), 봇 재량 한도(건당 5만원)를 지식으로 넣었다. 이 규칙들은 인터뷰에서 받은 정본 문서에 근거한다. 규정이 개정되는 상황은 시행일과 적용 기준 시점(가격 인하 보상은 주문 시점, 하자 접수 기한은 신고 시점)으로 판정하도록 했고, 기한이 지난 하자 신고도 거절하지 않고 확인 절차로 접수하게 했다. 프롬프트 탈취, "이전 지시를 무시해라", 개발자·조합장 사칭, 타 고객 정보 요구, 승인 기록 없는 "조합장님이 약속했다"에는 흔들리지 않고 고객 문의로 돌아오도록 방어 규칙을 따로 두었다. 섭취 후 이상 증상 같은 안전 사안은 문제없다고도 사고라고도 말하지 않고, 먼저 섭취를 멈추게 한 뒤 사람에게 이관하게 했다. 접수 API는 정책을 검사하지 않고 기록만 하므로, 허용 여부 판단은 에이전트가 책임진다는 전제로 조회, 고객 확인, 접수 순서를 규칙으로 고정했다.

## 2. 정보 획득 방식 — 어떻게 지식을 모았나

관계자 7명을 인터뷰했다: 이민준(청년회, 판매·CS), 고길동 조합장, 보라(홍보라), 구방만 기사, 김청년, 홍이장, 조억만. 이민준에게서는 판매환불규정, 개인정보처리방침, 조합원이용약관, 택배계약서 같은 정본 원문과 증빙 취급 및 권위 서열 규정을 받았다. 조합장에게서는 에스컬레이션 절차서, 권한 위임표, 부분환불 산식, 사업자 도매 거래 안내, 규정·대응방안 개정 이력을 받았다. 보라에게서는 프로모션 마스터(쿠폰·코드 원장)와 홍보 게시물 상태 기록을, 구방만 기사에게서는 시원배송 결항·집하 기록을, 홍이장에게서는 갯마을 조업·입고 기록과 수산 성어기·냉동 공급표, 위탁 판매 계약서를 받았다. 단골 고객 조억만의 증언은 당사자 진술로 분류해 규정의 근거로 쓰지 않았고, 실제 문서와 대조하는 단서로만 썼다. 받은 문서는 관계자별 요약 문서로 정리한 뒤, 서로 어긋나는 곳은 권위 서열과 개정 이력으로 가려서 지식 파일(`knowledge/`)로 옮겼다. 상품, 로트, 주문 같은 변하는 정보는 문서가 아니라 액션 API로 조회하도록 남겨 두었다.

## 3. 검증 방식 — 어떻게 확인했나

단위 테스트는 네트워크와 실제 API 키 없이 돈다. 액션 API는 `httpx.MockTransport`로, 모델 호출은 가짜 Anthropic 클라이언트로 대신해서 설정 로더, 카카오 요청·응답 형식, 도구 생성과 호출, 프롬프트 조립, 에이전트 루프, 세션, 출력 정리, 서버 조립을 확인한다. 특히 reset 엔드포인트가 에이전트 도구에 없다는 것, 테스트 케이스 ID 헤더가 모든 호출에 붙는다는 것, 응답이 항상 SimpleText 1개이고 500자를 넘지 않는다는 것을 테스트로 고정했다. 공개 TC는 `scripts/run_open_tc.py`로 재생한다. `--dry-run`은 키 없이 케이스별 고객 문의와 기대 `API-NN` 목록을 보여 주고, `--live`는 실제 에이전트로 첫 발화를 보내 호출한 API, 답의 글자 수, 소요 시간을 기대 대응과 대조해 PASS/FAIL로 요약한다. 실제 키로 하는 `--live` 재생과 배포 후 `smoke_skill.py` 확인은 오너가 수동으로 하며, 공개 TC는 인계 노트에 13건, 저장소 사본(`knowledge/open_cases.md`)에 15건으로 적혀 있다. [오너 확인: 재생한 TC 건수, 통과 건수, 실패한 케이스와 원인, 소요 시간 분포] 한 번 재생하면 액션 데이터가 바뀌므로 다시 재생하기 전에는 `--reset-first`로 초기화한다.

## 4. 주요 설계·구현

서버는 Python FastAPI 스킬 서버이고, 콜드스타트가 p95에 불리한 서버리스를 피해 Render에 상시 실행으로 배포한다. 모델은 `claude-haiku-5-5`를 Anthropic 공식 SDK로 부르며, 속도와 비용 때문에 effort는 `low`로 두었다. 시스템 프롬프트는 두 블록이다: 앞 블록은 응답 형식, 조회·확인·접수 순서, 계정 귀속, 레인 판정, 권한, 안전, 증빙, 기한, 비공개, 방어 규칙이고, 뒤 블록은 `knowledge/`의 지식 문서 전체이며 프롬프트 캐시 대상이다. 도구는 액션 API 명세(`actions.json`)에서 40개를 생성하고 번호는 공개 TC의 `API-NN`과 같으며, 시스템 블록과 도구 정의는 기동할 때 한 번만 만들어 모든 요청에 재사용한다. 에이전트 루프는 모델 호출을 최대 6회까지 반복하고 `refusal`과 `max_tokens` 종료를 따로 처리한다. 세션은 카카오 사용자 id를 키로 프로세스 메모리에 두고, 대화 중 전달되는 테스트 케이스 ID를 추출해 같은 케이스 내내 유지한다. 출력은 정리 단계에서 마크다운과 이모지를 걷어 내고 시스템 프롬프트나 키가 새면 안전한 문구로 바꾸며, 카카오 SimpleText 규격에 맞춘다. 지연은 4.2초 예산으로 제한하고, 요청에 콜백 URL이 있으면 즉시 대기 응답을 보낸 뒤 최종 답을 콜백으로 보낸다.

## 5. 아쉬운 점과 한계

음성은 인식하지 못해서, 텍스트 없이 음성만 오면 글로 남겨 달라고 안내하는 데 그친다. 대화 이력은 프로세스 메모리에만 있어 서버를 재시작하거나 배포하면 사라지고 워커나 인스턴스를 늘릴 수도 없으므로, Render 서비스를 워커 1개, 인스턴스 1대로 고정했다. 카카오는 스킬 서버의 응답을 5초 안에 요구하는데, 서버는 4.2초 안에 끝내려 하지만 도구를 여러 번 부르는 문의는 넘길 수 있고 그때는 안내문을 돌려주거나 콜백에 의존한다. 콜백의 대기 문구는 말풍선 한 건으로 세어질 수 있어 말풍선 수 점수에 불리할 수 있다. 확보하지 못한 문서가 있다: 박수복 어르신의 연락처를 받지 못해 작황·재해 기록과 농산 시즌 캘린더를 얻지 못했고, 이민준은 SKU 카탈로그와 가격 정책 시트의 위치를 알려 주지 못했다. 보라 쪽 인플루언서 계약서도 받지 못해서 이 영역은 액션 API 조회와 "규정에 없으면 모른다고 답하고 이관한다"는 규칙에 맡겼다. 관계자 10명 중 7명만 인터뷰했다.
